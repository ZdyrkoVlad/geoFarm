# geoFarm

## Запуск проєкта

1. **Встановлення залежностей:**
   Переконайтеся, що у вас встановлений [Node.js](https://nodejs.org/). У кореневій папці проєкту виконайте команду для
   встановлення всіх пакетів:
   ```bash
   npm install
   ```

2. **Запуск сервера для розробки:**
   Для локального запуску проєкту виконайте:
   ```bash
   npm run dev
   ```
   Після цього проєкт буде доступний у браузері (зазвичай за адресою `http://localhost:5173`).

3. **Створення збірки для продакшену (за потреби):**
   ```bash
   npm run build
   ```

## Патерни та архітектурні рішення (Patterns and design choices)

- **UI/UX перевірено для використання на планшетах і на ПК з роздільною здатністю від 768x1024. (Для смартфонів протрібно виконати редизайн, зміну UX, використання sidePanel тому виконано не було)
- **Приняте рішення використовувати ванільний Leaflet по задачі.
- **Використання спрощеної біблотеки DumbMGRS для додавання до карти грід-сітки для MGRS
- **Використання zustand для сторів щоб дотримуватись патернів єдине джерело правди

- **Розділення логіки і UI/UX** — візуальні компоненти відокремлені від бізнес-логіки.
- **Одне джерело істини** — єдине місце для зберігання стану додатку (Single Source of Truth).
- **Smart & Dumb Components** — поділ компонентів на контейнери, що працюють з даними, та прості юайні компоненти.
- **Стратегія (Strategy)** — рендеринг елементів залежно від типу об'єкта.
- **React Portals** — рендеринг React-компонентів поза основною ієрархією DOM (для інтеграції з мапою Leaflet).
- **Фільтрація без додаткового рендера** - обєкти на мапі робимо схованими напряму через icon.style.display = 'none' коли робимо фільтрацію або пошук
  Це не трігерить рендер що +. Але коли в нас буде забагато схованих обєктів то це мінус. Але при великій кількості
  точок потрібно використати Leaflet.markercluster
  P.S. спочатку була ідея використати стор і 2 списка станів. Один зберігавби всю інформацію, інший тільки ту яку нам потібно для відображення зараз
  (після фільтрації пошуку тощо) але робити перерендер на кожеш чих здалось дорого.

## План розвитку застосунку (App design-plan for future)

### 1. Моделі даних та стан

- [ ] **Розширення базових типів:** Додати ролі користувачів, прапорець (флаг) видалення (soft delete).
- [ ] **Історію змін ** Дадати історію змін об'єктів.
- [ ] **Відміна дій (Undo):** Додати стековий механізм undo для можливості відкатувати небажані дії (наприклад,
  випадкове видалення точки).
- [ ] **Розумний пошук** пошук з підказками упростить взаємодію користувача. Або ж пошук з використанням косинусної міри між векторним представленням слів чи текстами*(теоретично дешево)

### 2. Інтерфейс та взаємодія (UI/UX)

- [] **Мобільний інтерфейс** доопрацювання доробка інтерфейсу під мобільний додаток, тому що розмір екрану набагато менший за планшет. 
        Потрібен окремий UI/UX дезайн.

- [ ] **Позиціонування вікон:** Додати перевірку перекривання шарів біля краю екрана, щоб діалог створення точок/полів
  не перекривався з інформаційними вікнами.
  Статично прорахувати мінімальну відстань кліку до елементів UI. Якщо клік відбувається занадто близько до панелей або
  вікон — автоматично зсунути карту так, щоб точка кліку опинилася ближче до центру.
- [ ] **Підтримка клавіатури:**
    - Навігація між полями за допомогою стрілок (`←`, `→`, `↑`, `↓`).
    - Виклик функціоналу видалення обраного об'єкта клавішею `Delete`.
